## Design and workflow

- Kind: software; a working URL triage application for analysts. Existing FastAPI/Jinja stack retained.
- Palette: graphite-safety-orange. The first dealt lime palette conflicted with the existing orange client mark, so the next permitted palette was used.
- Typography: Host Grotesk and JetBrains Mono, weights 400/500, served locally with their SIL Open Font Licenses.
- Layout: centred hero containing the real multipart scanner; actual result report; URL/HTML method section; compact privacy footer.
- Motion: one-time hero entrance, unchanged kit hover/press layer, a silk-folds hero ground rendered and paused, and the dealt counter-rolls moment on the actual 24/53 feature counts. No scene or stock photographs.
- Voice: technical and dry; URL/HTML characteristics accompany the model estimate and are not presented as model attribution. No invented accuracy figures, customers, prices, or testimonials.

## Functional changes

- URL entry and optional HTML upload retain the existing /scan endpoint and fields.
- Native HTML disclosure, drag/drop, filename/size feedback, file removal, and size/type validation.
- Actual submission loading state and engine readiness from /health.
- Report separates the verdict, calibrated probability or uncalibrated fallback, observed signals, extracted features, and threat-intelligence status.
- Copy URL and download the actual report as JSON. No automatic URL persistence or new remote services.
- Mobile navigation supports keyboard use, Escape, and closes when focus leaves. The form still submits when JavaScript is unavailable.

## Preservation

No backend algorithms, model artifacts, feature definitions/order, calibration, thresholds, API responses, or evaluation records were changed for this frontend task. requirements.txt needs no new packages. Node is used only by the design verification tools, not to run the app.
